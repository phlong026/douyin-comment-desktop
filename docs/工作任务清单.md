# 抖音桌面端评论工具工作任务清单

> 状态：规划稿，全部任务均未开始。本文档完成不代表任何功能已经开发、验证或可用于生产。

## 1. 目标与边界

本项目验证并开发一套单机、单操作者使用的桌面端工具。默认路线为 Electron + TypeScript + 轻量 HTML/CSS 界面、本地 SQLite、独立本地执行进程，以及 AdsPower 本地控制 API + Playwright CDP。原生 Playwright 作为能力基线，比特浏览器只作为后续可选适配。

项目不使用抖音官方接口。页面 UI 操作是发送基线；在浏览器页面上下文内复用评论请求属于独立实验路线，必须由显式开关启用。外部 Node/Python HTTP 请求不会自动继承指纹浏览器的代理、Cookie 或设备环境，不得据此宣称已实现网络隔离。

“IP 隔离”在本文中仅指不同 profile 经验证使用预期的独立公网出口，不代表账号安全、防封或平台许可。任何平台能力和接口稳定性都不作承诺。

完整需求范围由以下四个维度组成，共 16 个组合，当前全部为 `UNVERIFIED`：

| 维度 | 取值 |
| --- | --- |
| 目标归属 | `own`、`other` |
| 作品类型 | `video`、`note` |
| 评论深度 | `root`、`reply` |
| 内容类型 | `text`、`image_text` |

`image_text` 必须是在同一条评论中同时包含图片和文字。给图文作品发送纯文字评论不算图片评论。P1 可以交付文字试验版，但不能据此宣布完整需求完成；未支持组合必须保持阻塞状态，不能通过改名、降级或缩小口径消除。

## 3. 实施约束

- 初始全局并发固定为 1；每个 profile、每个账号同时最多执行 1 个任务。初期只用 1–2 个 profile 验证，这不是安全频率结论。
- 初期所有内容必须人工预览并批准。批准记录绑定账号、目标、原评论、内容 hash、图片 hash、执行 route、profile 网络配置版本和 TTL；任一字段变化或 TTL 到期后必须重新批准。
- 点击发送或写请求之前，先持久化提交意图并进入提交风险区；意图本身不证明请求已发出。进入风险区后超时、进程崩溃或结果无法确认时进入 `UNKNOWN`，不得自动重发。本地去重不等于平台 exactly-once。
- 任务必须支持暂停、取消、过期、账号/profile 禁用、账号受限停发和重启恢复。验证码、签名或平台限制不得绕过；受限任务不得通过轮换 IP 或账号继续执行。
- Cookie 留在浏览器厂商 profile 中。敏感凭证使用操作系统安全存储，不进入渲染进程、日志、HAR 或导出文件。浏览器厂商本地控制接口只允许回环访问并启用鉴权。
- 代理断开时必须失败关闭，不得静默改为本机直连。UI 路径和页面内请求路径都要分别核验实际公网出口及媒体上传出口。
- SQLite 驱动选择在环境任务中冻结，不在任务执行前预设或新增依赖。
- 所有测试设计和失败用例必须先于对应实现任务完成。

“工作量级”用于拆分：小为单一边界任务，中为跨模块集成，大为关键流程或组合回归，探索表示工作量取决于平台实际能力。它们不是人日或报价。当前没有本项目实测依据，不给出精确总工期。P0-11 根据实际页面、浏览器兼容性和故障样例估算 P1/P2；每阶段结束再修订剩余排期。

按三个可验证的纵向切片推进：

1. **环境与能力探针**：P0 先确认材料、浏览器连接、实际出口、文字/图片能力和请求复用边界。
2. **安全的文字闭环**：P1 测试先行，完成导入、审核、执行、核验、暂停和恢复；取消/撤回竞态在此阶段解决。
3. **条件性的完整功能与交付**：P2 复用现有状态机和证据组件扩展图片/回复/选定请求路线，P3 完成适用范围的验证和打包。

P0-04 是所有真实账号登录、请求观察与评论测试的前置门槛；已有批准范围可复用，新增账号、目标、内容、数量或时段须更新记录。Mock/fixture 不受真实发送材料缺失影响，可先行开发和验证。

## 10. 停止与降级条件

| 条件 | 处理 |
| --- | --- |
| 抖音桌面网页没有某个组合所需入口 | 该组合保持 `BLOCKED`；不以不同能力替代，不进入完整需求完成口径 |
| `image_text` 不能在同一条评论展示图片和文字 | 停止图片完整范围开发；P1 文字版可独立继续，但必须标明缺口 |
| AdsPower 本地 API/CDP 当前环境不可用 | 可降级到原生 Playwright 做 UI 能力基线；不得把它算作 profile/IP 隔离交付；AdsPower 集成继续保持阻塞 |
| 页面内请求依赖无法稳定取得的签名、一次性状态或保护机制 | 关闭实验开关，保留 UI 基线路线；不实施绕过 |
| 代理断开后会静默直连，或无法证明评论与媒体上传的实际出口 | 停止对应 route；修复失败关闭前不得执行评论任务 |
| 出现验证码、登录挑战、账号受限或平台限制提示 | 暂停并禁用对应账号/profile，交由人工处置；不得轮换 IP 或账号继续原任务 |
| 提交后结果无法确认 | 标记 `UNKNOWN` 并人工核验；不得自动重发 |
| 开源代码无明确许可证或许可证与交付方式冲突 | 不复用该代码；只保留独立实现所需的公开行为参考 |
| 凭证、Cookie、代理密码进入渲染进程、日志、HAR 或导出 | 阻断发布；完成清理、轮换受影响凭证并重新验证 |
| 取消或撤回批准与提交发生竞态且无法证明不会误发 | 阻断对应功能和发布，直到提交边界与恢复行为有测试证据 |

## 11. 完成口径

- 单个任务只有在其“可检验完成条件”全部满足、证据已归档后才能勾选。
- 阶段完成必须满足该阶段所有必需任务；条件任务无法执行时必须保留阻塞和理由。
- P1 完成只表示文字试验版完成。
- 只有 P2-09 的 16 个组合分别在其选定路线通过，才能声明“完整评论范围完成”；接口复用是否采用须单独报告。
- P3-05 完成只表示形成可交付候选版本，不表示平台将持续兼容，也不表示账号不会受限。
