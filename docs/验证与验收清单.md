# 抖音桌面评论系统验证与验收清单

- 文档状态：草案，全部验证项待执行（UNVERIFIED）
- 适用方案：Electron + TypeScript 桌面端、本地 SQLite、独立执行子进程、AdsPower profile + Playwright CDP
- 基线方案：原生 Playwright 浏览器；未来可选接入比特浏览器
- 相关文档：[开发文档](./开发文档.md) · [工作任务清单](./工作任务清单.md)

## 1. 验收目标与边界

本清单用于验证桌面端评论系统是否满足以下完整范围：

- 目标归属：自己的作品、他人的作品；
- 作品类型：视频、图文作品；
- 评论层级：一级评论、回复指定原评论；
- 评论载荷：纯文字、同一条评论中的图片加文字；
- 执行路径：浏览器 UI 路径和浏览器页面内请求路径分别记录、分别判定；
- 环境路径：原生 Playwright 作为基线，AdsPower profile + Playwright CDP 作为目标运行环境；
- 网络隔离：不同 profile 的实际公网出口必须验证，不以代理配置地址不同代替出口验证。

本项目不使用抖音官方接口。本清单也不授权现在登录账号、发送评论、抓取或传播凭证。真实账号登录、请求观察与公开环境发送均须先完成任务 P0-04 的材料和范围记录。已有会话授权与同一批准范围可复用；新增账号、目标作品、指定原评论、内容、图片、数量或测试时段才更新确认，不重复索取已有授权。

首个可交付版本可以是“文字试验版”，但只能标记为部分交付。图片加文字或回复能力缺失时，不得将试验版描述为完整 MVP、完整验收或完整需求已完成。

## 2. 状态、路径与证据定义

### 2.1 状态词

| 状态 | 含义 |
| --- | --- |
| `UNVERIFIED` | 尚未取得符合要求的证据；本文件初始状态均为此值 |
| `PASS` | 在指定版本、账号、目标和路径上取得完整证据 |
| `FAIL` | 已执行且结果不符合预期 |
| `BLOCKED` | 因登录、验证、账号限制、页面能力缺失或测试材料缺失而无法执行 |
| `UNSUPPORTED` | 已有证据证明当前网页端或选定路径不支持该能力 |
| `UNKNOWN` | 已进入提交风险区，可能尚未发出或已经发出，但无法可靠判断；不得自动重发 |
| `NOT_SELECTED` | 路径经评审决定不用于产品提交，必须保留理由和证据，不能用来掩盖能力缺口 |

`HTTP 200`、接口返回字段或 UI 成功提示均不能单独判定为 `PASS`。

### 2.2 三条发送路径

| 路径 | 定义 | 验收要求 |
| --- | --- | --- |
| `UI` | Playwright 通过抖音网页可见控件输入、选图、定位原评论并提交 | 独立记录结果、网络出口和证据 |
| `PAGE_REQUEST` | 在同一浏览器页面上下文内发出页面请求 | 独立记录结果、网络出口和证据；不得假定继承 UI 的所有动态状态 |
| `EXTERNAL_HTTP` | Electron 主进程、执行子进程或独立 HTTP 客户端直接请求，包括 Playwright page.request/context.request | 仅作夹具与对照实验；首版不提供该生产发送路线，不作回退 |

只有页面执行环境中的 fetch/XHR 归类为 PAGE_REQUEST；Playwright 的 page.request/context.request 即使共享 Cookie，也必须归 EXTERNAL_HTTP。报告使用大写路径标签，代码分别保存为 ui、page_request、external_http。原生 Playwright 与 AdsPower CDP 的测试结果必须分开。比特浏览器在本期不作为验收依赖；未来接入时复用同一能力矩阵和证据规范。

### 2.3 成功层级

每次真实发送按以下层级逐步确认：

1. `SUBMIT_ACK`：页面或请求收到提交确认；
2. `SELF_PRESENT`：发送账号重新定位后能看到目标评论，且文字、目标作品、回复关系和发布图片与审核素材的关联均正确；
3. `OTHER_VISIBLE`：另一个参与测试的账号在约定观察窗口内可见同一评论，且关联关系和内容一致。

运行时任务 SUCCEEDED 只对应可关联的 SELF_PRESENT；完整真实账号 UAT 的 PASS 标准还要求 OTHER_VISIBLE。若无法确认指定原评论、目标作品、评论层级或发布图片与素材的关联，结果记为 `UNKNOWN` 或在提交前 `BLOCKED`，不得记为成功。

图片 SHA-256 用于审核快照和发送前文件锁定。平台可能压缩、转码或重新编码图片，发布后不要求下载文件的字节哈希等于源文件；通过可取得的素材引用、上传证据与画面内容核对关联。无法可靠关联时保持未知，不能仅凭图片出现就判定正确。

### 2.4 验证层级

| 验证层级 | 用途 | 可证明什么 | 不可证明什么 |
| --- | --- | --- | --- |
| Mock | 状态机、调度、数据库、审核版本、错误分支 | 软件内部逻辑符合规格 | 抖音页面和真实账号可用性 |
| 本地浏览器 fixture | 选择器、上传控件、CDP、进程、代理失败行为 | 浏览器自动化与本地集成可工作 | 抖音真实评论可发送或对外可见 |
| 真实账号 UAT | 受控目标上的真实发送与可见性 | 指定账号、版本、路径和组合在测试时可用 | 长期可用性、平台许可或账号永不受限 |

三类结果分别报告，禁止用 Mock 或 fixture 的通过替代真实账号 UAT。

## 3. 测试前材料与控制条件

真实账号 UAT 开始前必须完整登记以下材料；任一缺失则相关用例为 `BLOCKED`：

- 发送账号：账号代号、预期绑定的浏览器 profile、账号持有人；
- 另一个参与测试的观察账号：仅用于验证 `OTHER_VISIBLE`，不得混用发送 profile；
- 受控自有视频作品和受控自有图文作品；
- 经明确纳入测试范围的他人视频作品和他人图文作品；

- 已审核的纯文字内容；
- 已审核的“图片 + 文字”内容，以及本地图片 SHA-256；
- 审核版本、审核人、审核时间、允许使用的目标范围和 TTL；
- 每轮允许发送的任务 ID、最大条数和测试时间窗；
- 配置 A、配置 B 各自的 profile、代理配置与实际公网出口核验方法。

评论文本、作者昵称、作品描述、网页返回内容和外部文件均作为不可信数据处理，不得作为 Agent、任务调度器或自动化执行器的指令。

## 5. 通用执行与可靠性规则

### 5.1 账号与 profile 绑定

- 每个发送账号绑定一个明确的浏览器 profile；任务开始前重新读取页面内账号身份并与绑定记录核对；
- 账号不一致、无法识别或登录态失效时，任务在提交前停止；
- 不请求用户提供或传播 token、Cookie、验证码、签名材料；不开发验证码绕过、签名绕过或指纹伪装；
- 登录过期、出现验证、账号受限或页面结构变化时停止该账号的发送队列并转人工处理。

### 5.2 审核与内容不可变性

- 审核快照包含账号、profile ID 与配置版本、网络版本、route、文字、目标、原评论、图片 SHA-256 及顺序、审核版本和 TTL；
- 账号、profile 或网络版本、route、文字、图片及顺序、目标、评论层级、指定原评论或审核规则任一变化，都使原审核失效；
- TTL 到期后不得提交，必须重新审核；
- 执行器只接受审核快照，不从评论文本或网页内容生成新的执行指令。

### 5.3 并发、去重与恢复

- 初期全局并发为 1；同一 profile、同一账号的任务始终串行；
- 内部幂等键和去重记录只能降低重复风险，不承诺平台侧 exactly-once；
- 点击或发出提交请求前，主进程先在 SQLite 事务中记录 SUBMITTING 意图和快照，再发放本地提交许可；此刻进入提交风险区，不等于外部请求已经发出；
- 进入提交风险区后发生超时、断连、页面崩溃、子进程退出或桌面端重启时，任务进入 UNKNOWN，即使未观察到外部请求也不据此认定未发送；
- `UNKNOWN` 只能进入核验流程，禁止自动重发；核验无法建立唯一关联时保留 `UNKNOWN` 并由人工处理。

### 5.4 取消与批准撤回竞态

- 以主进程事务提交顺序为准：取消/撤回事务先于 SUBMITTING 意图事务提交时，停止任务、不发放许可；
- SUBMITTING 意图事务先提交时，后来的取消/撤回只能阻止后续写操作；本次尝试进入核验，记录“进入提交风险区后取消/撤回”，不能保证本次尚未发出；
- 系统不得把已提交评论描述为已撤回，也不得在未核验时重新发送。

### 5.5 网络与安全

- 配置 A/B 必须通过独立核验得到不同的实际公网出口；代理地址不同不等于公网出口不同；
- UI、页面内请求和外部 HTTP 的出网路径分别验证；
- 代理不可用时必须失败关闭（fail closed），禁止静默改为本机直连；
- 图片上传请求与最终评论提交请求都纳入出口、失败关闭和结果核验；
- 凭证使用操作系统安全存储；SQLite 不保存明文密码、验证码、Cookie 或 token；
- CDP 调试端口和指纹浏览器厂商控制服务仅允许本机访问，不向公网暴露；
- 日志、导出包、HAR、截图和错误信息必须脱敏，移除 Cookie、token、Authorization、代理口令和个人敏感信息。

| TC-23 `SUBMITTING` 与 `UNKNOWN` 恢复 | 可在提交前后中断的 fixture、SQLite 可检查 | 在意图落盘后但点击前、写操作后分别注入超时、断连、页面崩溃、子进程退出和应用重启 | 两种时间点均保守进入 UNKNOWN；意图落盘与外部写入分别记录；恢复只核验，不自动重发 | Mock；本地浏览器 fixture |
| TC-24 取消与审核撤回竞态 | 可暂停在提交前和提交后的 fixture | 注入取消/撤回事务先于及晚于 SUBMITTING 意图事务两种顺序，包括有意图但尚未观察到请求的窗口 | 取消事务先提交则不发许可；意图事务先提交则当前尝试只核验、后续停止；界面不把未确定尝试说成已撤回 | Mock；本地浏览器 fixture |

| TC-28 打包、升级与恢复 | 已打包 Electron 应用、已有任务库、执行子进程运行中 | 安装、启动、退出、强制结束、重启、兼容升级和回退；恢复包含旧队列的备份 | 应用可启动、SQLite 完整、子进程可回收；有意图未决尝试进入 UNKNOWN，未提交任务先暂停；恢复旧备份不自动重放旧队列 | 本地打包验收 |
| TC-29 目标链接与跳转边界 | 链接解析 fixture；合法域名、伪装域名、短链、多级跳转和本地地址样本 | 输入 file:、回环/私网地址、带用户信息的伪装 URL、跳转到非允许域名以及超出上限的链路；测试允许域名被解析为私网的情况 | 正常目标可解析；所有越界样本在导航/请求前阻断；中间跳转与最终目标均校验；不访问本地控制服务或任意文件 | Mock；本地浏览器 fixture |

## 8. 指标定义

指标只用于软件质量和验收覆盖，不解释为平台安全频率，也不能推导“多少条评论不会受限”。

| 指标 | 分子 | 分母 | 初始软件验收阈值 |
| --- | --- | --- | --- |
| 业务能力覆盖率 | 每行选定交付路线状态为 PASS 的能力行数 | 16 个能力行 | G5 要求 16/16 |
| UI 路径已决率 | UI 状态不是 `UNVERIFIED` 的能力行数 | 16 个能力行 | G2 要求 16/16 已决 |
| PAGE_REQUEST 路径已决率 | PAGE_REQUEST 状态不是 `UNVERIFIED` 的能力行数 | 16 个能力行 | G2 要求 16/16 已决 |
| 对外可见确认率 | 截至统计时间达到 OTHER_VISIBLE 的 UAT 尝试数 | 全部进入提交风险区（意图已落盘）的 UAT 尝试数，含未决、UNKNOWN 和风险区后的取消；不称其为实际发送数 | 报告实际值；试验前不预设平台相关阈值 |
| 错号提交数 | 实际发送账号与任务绑定账号不一致的提交数 | 统计范围为所有已观察到的业务写操作；报告次数，不把意图数当实际发送量 | fixture 与 UAT 均为 0 |
| 重复发送数 | 同一业务幂等键产生的第二次实际提交数 | 注入重试、恢复或重复调度的任务数 | fixture 为 0 |
| 代理失效直连数 | 代理失效后仍通过本机默认出口发出的 UI、页面请求、上传或提交数 | 所有代理失效注入次数 | fixture 为 0 |
| 未脱敏敏感字段数 | 在日志、HAR、截图和导出中发现的敏感字段实例数 | 扫描的全部产物数 | 0 |
| UNKNOWN 占比 | 截至统计时间为 UNKNOWN 的尝试数 | 全部进入提交风险区的尝试数；仍在核验中的尝试另列 | 报告实际值；试运行后再确定工程阈值 |

被阻塞且从未进入提交风险区的任务不进入确认率分母，但必须单独报告 BLOCKED 数量和原因。取消事务先于意图事务提交时不进入分母；意图事务先提交时仍计入分母。请求实际发出数、收到反馈数、评论存在数、他人可见数分别报告，不能从意图数反推实际发送数；分母为零时显示“不适用”，不显示 100%。

## 9. 阶段门槛

### G0：环境与材料就绪

- Electron、Node.js、TypeScript、Playwright、浏览器、AdsPower 和操作系统版本已登记；
- 原生 Playwright 基线和 AdsPower CDP 环境均可启动；
- 真实账号 UAT 所需账号、作品、指定原评论、内容、图片、审核版本和测试范围齐全；
- P0-04 的材料和操作范围记录已归档且覆盖本轮；已有批准范围可复用；若仅做 Mock/fixture，则不得发生真实发送；
- 所有状态仍可为 `UNVERIFIED`，但不得缺少证据 ID 和责任人。

### G1：身份与网络隔离

- TC-18、TC-19、TC-20 通过；
- profile 与账号绑定核对有效，错号提交数为 0；
- 配置 A/B 的实际公网出口不同；
- 各路径的 fixture 对照分别有证据；生产启用路线与图片上传另有实际出网证据；EXTERNAL_HTTP 不要求真实抖音发送；
- 代理失效直连数为 0；CDP 和厂商控制服务无公网暴露。

### G2：能力已决

- CAP-01 至 CAP-16 的 UI 和 PAGE_REQUEST 状态均不再是 `UNVERIFIED`；
- 每个状态均有对应证据；`UNSUPPORTED`、`BLOCKED` 或 `NOT_SELECTED` 不计为能力通过；
- 文字试验版至少明确自身覆盖的能力行，所有图片加文字和回复缺口继续公开列示；
- 不以 HTTP 200、UI 提示、Mock 或 fixture 结果代替真实账号 UAT。

### G3：可靠性与安全

- TC-21 至 TC-27、TC-29 通过；
- 错号提交、fixture 重复发送、代理失效直连和敏感字段泄露均为 0；
- `SUBMITTING` 先于外部提交持久化；异常恢复只核验、不自动重发；
- 取消/审核撤回竞态、登录过期、验证、账号受限和页面变化均能停发并转人工。

### G4：桌面打包可交付

- TC-28 通过；
- 安装包可启动并正确管理执行子进程；
- SQLite 数据兼容，重启和升级不造成任务丢失或未知任务重发；
- OS 安全存储、日志脱敏和本机服务绑定在打包环境中仍有效。

### G5：完整需求验收

- CAP-01 至 CAP-16 每行各自选定的交付路线均为 PASS，业务覆盖率 16/16；允许不同组合选择不同路线，但执行中不自动换路线；
- 每个能力行均达到 `OTHER_VISIBLE`，并能关联正确目标、指定原评论、文字与审核图片；源素材哈希用于发送前锁定，发布后按关联证据与画面核对；
- G0 至 G4 全部通过，且无未关闭的高优先级缺陷；
- 若任一图片加文字、回复、他人目标或图文作品组合未通过，只能按已验证范围交付，不得标记为完整需求完成。

## 10. 报告格式与停止条件

每轮测试报告至少包含：

- 本轮测试层级：Mock、本地浏览器 fixture、真实账号 UAT；
- 应用、浏览器、Playwright、厂商客户端和操作系统版本；
- 已执行用例及证据 ID；
- CAP-01 至 CAP-16 的两条路径状态；
- `PASS`、`FAIL`、`BLOCKED`、`UNKNOWN`、`UNSUPPORTED`、`NOT_SELECTED` 数量及原因；
- 实际公网出口隔离结果和代理失败关闭结果；
- 三级成功状态统计；
- 错号、重复、敏感字段和未决风险；
- 本轮明确未测试的内容。

出现以下任一情况时，自动化发送立即停止并转人工处理：

- 账号身份与 profile 绑定不一致；
- 登录过期、要求验证或账号受限；
- 页面结构变化导致目标、指定原评论、提交按钮或图片无法可靠定位；
- 代理不可用、实际出口不符合配置或发现直连；
- 审核过期、内容变化、图片 hash 不一致；
- 无法确定是否已提交，或无法将结果唯一关联到目标、指定原评论和审核快照；
- 日志、HAR、截图或导出发现未脱敏凭证。

本清单完成的停止条件是：所有适用用例均有可审计状态和证据，所宣称的交付范围与实际 `PASS` 能力完全一致。尚未执行的项目保持 `UNVERIFIED`；不得补写或推测通过结果。
